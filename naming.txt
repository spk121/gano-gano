                          Coordinate Systems

There are a crapload of coordinate systems for the editor, and I try
to be consistent about their naming.

* (C,R) The logical column and row of character in a text buffer.
  (0,0) is the first character on the first line.  Hanzi, Kanji and
  tabs all take up one unit in this representation.

* (Cv,Rv) The visual row and column of a character in a text buffer.
  These take into account the width of characters and tabs. The origin
  (0,0) is the first character on the first line.

* (Xw,Yw) The main window coordinates.  The coordinates Xw,Yw are
  measured in cells from the top left corner of the editor window.
  The origin (0,0) is the top left corner of the screen.

  Inside the main window are three subwindows: the top, editor, and
  bottom windows.  Each of those subwindows has the same width.  So,
  there are three different subwindow coordinate system.

* (Xt,Yt) Top windows coordinates
* (Xe,Ye) Editor coordinates
* (Xb,Yb) Bottom window coordinates

                         A Rant about Scheme

Everyone that has ever started with Lisp or Scheme originally has a
sort of 'syntax shock'.  There is so little syntax, so few clues to
the meaning of things, that it is disorienting.  No way to distinguish
between the 'if' branch and the 'else' branch; no way to intuit from a
token if it is a variable, function, or macro.  Just a sea of
parentheses, hyphens, and lower case letters.

Eventually the programmer becomes accustomed to the lack of syntax,
and then even becomes perversely proud of their mastery of Scheme's
lack of handholding.  They come to think that this is the way it
should be.  "Look at how elegant, how simple," they exclaim, from
their beige desks in their unadorned white rooms.

Scheme is the most modernist and heteronormative of all the computing
languages, so afraid of a bit of swish, a bit of sparkle.  Much like
the white-walled modernist glass houses that cover the landscape in
Santa Monica, we are supposed to be impressed by its cleanliness and
the big unadorned windows.  I am not Santa Monica: I am West
Hollywood.  Let us not fear being fabulous.

Everyone's first impression is absolutely right.  Scheme needs more
visual clues to the meaning of things.  I'm going to try to bolt on as
much syntax as I possibly can.  Square brackets, visual clues to
distinguish between procedures, parameters and variables, even *gasp*
Capital Letters.  R6RS permits them all, and I will not reject them
out of misplaced desire for orthodoxy.

                        The Names of Variables

Back in the dark ages of the 1990s, there was a practice that came
into fashion for a few years before dying out, called Hungarian
Notation.  It was universally ridiculed, and then rendered obsolete
with improvements in Microsoft Visual Studio and the move to managed
languages.

It was rendered obsolete by editor improvements like Intellisense,
where hovering over a variable gives its type.  Yeah, yeah, Scheme
isn't a stronly typed language.  I know.  That's no excuse for
anarchy.

Gano is my personal project, so I'm going to do whatever the heck I
want, so, for my own personal amusement, I'm going to use a type of
Hungarian Notation.

Here are my rules.

1. Procedures

a. Procedures names begin with transitive verbs.  If a procedure is a
pure function that operates on its parameters and returns a single
value, it is named something like AFromBCD.

b. Procedures are Pascal case.

2. Variables

a. Variables are camel case.

b. Variable names are always begin with nouns.  If there are any
adjectives they come after the nouns. xCurrent, not currentX.  If a
variable contains a list or an array, the noun must be plural.  If it
does not, the noun is singular.

b. There are standard suffixes for variables that must be used
- First: an index to 1st element in a set
- Last: an index to last element in a list
- Lim: the upper limit to indices in this set
- Min: the actual 1st element in a set
- Max: the actual last element in a set
- Mic: the current 1st element in a set for this case
- Mac: the current last element in a set for this case
- Sav: temporary save value
- Nil: a value that is always illegal
- Src: a source
- Dest: a destination

e. There are some standard prefixes
- i: index into an array
- c: count of things
- d: a difference between two instances
- rg: a range, aka a collection of things where the order has meaning
- mp: a map, an array whose purpose is to convert on thing into
another
- e: an array element
- v: a global variable
- f: a flag

So, given a collection X
- rgX- the set
- iX - an index into the set
- iXFirst - an index to the first element in the set
- iXLast - an index to the last element in the set
- iXLim - the upper limit of indices, aka iXLast + 1
- eX - an element extracted from the set
- eXMin - the first element extracted in the set
- eXMax - the last element extracted from the set

f. The normal Scheme coding standards encourages using the hyphen, the
question mark, and the asterisk in multiple contexts.  I reject that.
No variable name should have a hyphen, an asterisk or a question mark
in the name.  They are math operators, and just confuse.

3. Brackets

Square brackets will be used in let, cond, and do statements,
according to the suggestions in R6RS appendix C.
